* Phase 0.5 -- baseline corpus (constructs already ported)
** DONE fix Codegen5.ml's immrot + offset_to_R12 (address-of-global)
   Both were already-flagged stubs ("less: x - BIG at some point",
   "TODO: port full code of immrot") -- finished properly rather than
   patched around, since a real immrot (full 8-bit-rotated-immediate
   search) is needed generally, not just for this one case. Ported
   goken's actual algorithm (5l/span.c immrot(): try each of the 16
   even rotations, unsigned 32-bit arithmetic) and the BIG bias
   ((1<<12)-4, 5l/l.h) that offset_to_R12 was missing. Caught by
   kitchen_sink.s (below) using two GLOBLs: with only one global at
   offset 0 (every earlier fixture), xix's old "offset=0 -> pool,
   else fast ADD path" happened to agree with goken by coincidence;
   a second global at a nonzero offset exposed that goken's real
   condition is "immrot(offset-BIG) succeeds and isn't exactly 0",
   which for any small data segment is essentially never true (BIG
   is meant for symbols positioned near it in a *large* segment) --
   so goken pool-loads both, while xix's old code fast-pathed the
   nonzero one. Verified: full baseline (5 fixtures) + make test
   (134/134) still pass after.
** DONE add tests/linker/arm_diff/kitchen_sink.s (hand-written, not from goken)
   Combines ADD/SUB/MUL/SLL, a BL/RET local call, address-of-global,
   and write/exit in one straight-line program -- broader coverage
   per fixture. Writing it caught a real bug (see immrot/BIG entry
   below), then an unrelated real *finding* once fixed: an earlier
   version used CMP+BEQ to pick between two exit messages, and goken
   turned out to duplicate the short exit epilogue (mov r7,#1; svc
   #0; pop {pc}) into *both* branches instead of having one branch
   to a shared tail -- i.e. goken doesn't always emit the branch our
   codegen would for a "B labelname" whose target sits past another
   block; something in 5a/5l's asm/noop layer decides to duplicate
   short tails instead. Real, but distinct from anything in our case
   list -- not chased now. Rewrote the fixture branch-free instead of
   chasing it. Worth its own investigation later if CMP/Bxx-heavy
   fixtures are added.
** DONE extend corpus: tests/linker/arm_diff/{exit_linux_arm,addr_arm,call_arm}.s
   Moved hello_linux_arm.s from tests/linker/ into tests/linker/arm_diff/
   (a subfolder, not its own top-level dir: these fixtures exercise
   assembler codegen + basic exec layout more than linking proper --
   one object file each, no cross-object resolution -- but it's
   still o5a+o5l's combined output being compared, and a sibling
   tests/linker/mips_diff/ is expected once MIPS gets this treatment
   too). Added 3 more from goken's own tests/s/{exit,variants}/: exit_linux_arm.s
   (minimal exit(42), no data section -- caught the elfstrtab 1-byte
   bug above), addr_arm.s ($sym(SB) address-of-global + pointer-valued
   DATA), call_arm.s (BL to a symbol, two TEXT procs). All 4: PASS
   byte-identical + PASS same qemu-arm exit code. Also fixed
   diff-arm.sh: `set -e` was aborting the script on a fixture's
   intentional non-zero exit code (exit_linux_arm.s exits 42).
** DONE tests/linker/arm_diff/hello_linux_arm.s: cmp -l clean vs goken
   PASS: byte-identical (4112 bytes both sides). Last 6 bytes closed
   in Layout5.ml: implemented goken's checkpool()'s "true end of
   program" flush trigger (`if(p->link==P) flushpool(p,true)`) --
   inserting a synthetic self-branch ("B .", an unreachable trap)
   right before the flushed literal pool, matching goken's always-
   guard-against-fallthrough behavior even though it's dead code
   here. The self-loop falls out naturally from gbranch_static
   reading the branch's own .branch field. Heavily commented in
   Layout5.ml since the literal-pool mechanism itself (not just this
   fix) wasn't well understood going in; added two permanent
   Logs.debug traces (pool-entry-added, pool-flushed) for next time.
   Mid-function early-flush (pool > ~4KB or LDR offset overflow) is
   NOT implemented -- pools must stay small; a real limit, not just
   a decision to revisit later. Verified full `./test-arm.sh` +
   `make test` (134/134) after.
** DONE tests/linker/arm_diff/hello_linux_arm.s: runs correctly under qemu-arm
   Root cause found and fixed: linker/Flags.ml's kencc_compatible
   defaulted to true, which sets the MOV instruction's Rn field to the
   destination register instead of 0 (Codegen5.ml:441). goken always
   encodes Rn=0 for MOV; qemu-arm's decoder actually SIGILLs on the
   Rn=rt encoding (verified by hex-patching just those 3 bytes in an
   otherwise-crashing binary -- that alone fixed it). Fixed by
   flipping the default to false. One-line fix, no case/logic touched.
