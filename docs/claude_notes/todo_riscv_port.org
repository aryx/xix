   2-register and 1-register-vs-zero forms). New op_btype (B-type

   `b_condition * gen * A.branch_operand` to

   Object_file.version 14->15) since, unlike MIPS's split BEQ/BNE-
   vs-Bxx AST design, RISC-V's 6 hardware branches are ALL genuine
   2-register comparisons per goken's uniform case-3 handling --
   Parser_asmi.mly gained a second `TB gen TC reg TC rel` rule for
   the explicit-middle-register form.
   Discovered by reading goken's own yacc grammar (ia/a.y), not just
   asm.c: the 1-register form (`BEQ S,L`, no explicit middle reg) is
   rewritten AT PARSE TIME to `from=regzero, reg(middle)=S` --
   i.e. the explicit register lands in the *middle* slot, not
   `from`. This is NOT the usual "middle defaults to zero" pattern
   every other optional-middle-register case uses (MIPS's case 2/9/
   0/1, RISC-V's own case 0/1) -- confirmed by decoding the actual
   instruction bytes (goken's disassembler text is ambiguous/
   misleading about operand order), not just reading the C source.
   Also newly discovered (out of scope, documented at length in
   branch_case3.s's own comment): goken's assembler recognizes the
   "branch to L1; immediately followed by unconditional JMP to L2"
   idiom (a classic if/then/else compiler pattern) and rewrites it --
   inverts the branch to jump straight to L2, then *relocates* L1's
   code to the end of the function, threaded back in with its own
   JMP. A real code-layout/CFG optimization in goken's own assembler,
   not something this port replicates; worked around by using an
   "invert-and-skip-one-instruction" idiom instead (branch directly
   over a single following instruction, no intervening JMP), which
   doesn't trigger it.

   both operand forms, chained into the exit code) and its
   riscv64_diff copy. PASS byte-identical + PASS same exit code (127)
   on both RV32 and RV64.

* Notes for later
** MOVB/MOVH/MOVBU/MOVHU not wired in the assembler

** Rewritev.ml (MIPS) may have a latent leaf-with-locals gap
   Found while reading goken's il/noop.c for RISC-V's 3-way leaf/
   frame logic: MIPS's Rewritev.ml only has a 2-way split (leaf-with-
   no-locals vs everything else), always doing the full RLINK save/
   restore even for a leaf procedure that merely has locals. Whether
   goken's vl/noop.c actually has the same 3-way distinction (making
   this a real MIPS gap) wasn't checked -- no MIPS fixture currently
   exercises a leaf-with-nonzero-declared-size TEXT to expose it
   either way.
